# 真实账号验证计划

这份清单用于 `codex/compatibility-hardening` 分支进入人工验证前的最后准备。
验证由使用者在本机完成账号输入、验证码、人脸验证和直播操作；测试代码不读取或导出
密码、Cookie、Token、验证码内容或推流密钥。

## 开始前

1. 使用独立验证 Bundle ID 重新打包并通过只读 Bundle 预检。示例：

   ```sh
   cd "$WORKTREE/macos-livehime-adapter"
   LIVEHIME_APP_PATH="$PWD/dist/LiveHimeMacAppValidation.app" \
   LIVEHIME_BUNDLE_ID="local.livehime.macos.validation" \
   LIVEHIME_BUNDLE_NAME="LiveHime macOS Validation" \
   LIVEHIME_BUNDLE_VERSION="0.1.0-validation" \
   OBS_APP_SOURCE="/path/to/obs-studio/build_macos/frontend/RelWithDebInfo/OBS.app" \
   ./scripts/package-app.sh
   ./scripts/verify-bundle.sh dist/LiveHimeMacAppValidation.app
   ```

   验证包必须使用 `local.livehime.macos.validation`；不要用正式包的 Bundle ID，
   否则 Keychain 和 WebKit 网站数据可能复用已安装版本。
2. 关闭单独安装的 OBS，避免 WebSocket 端口和权限归属混淆。
3. 确认麦克风、摄像头、屏幕录制和系统音频权限已经按需授予。
4. 准备一个可以安全开播、随时关播的测试时段；不要在正式活动直播中首次验证。
5. 不把诊断文件、终端输出或截图中的账号、Cookie、Token、验证码和推流密钥上传。

## 第 1 轮：登录、会话和换号

人工操作：

1. 启动验证包，完成账号密码或二维码登录。
2. 如果页面要求图片验证码、短信、二次验证或人脸验证，按平台页面完成，不绕过验证。
3. 等待 LiveHime 显示已登录、用户名、直播间和分区。
4. 点击退出登录，确认页面回到登录页。
5. 使用另一个可测试账号登录，确认旧账号没有自动恢复。

通过条件：登录状态稳定保存；退出后 Cookie 清理完成；换号后显示新账号；身份读取失败时
界面显示具体 HTTP/API/结构错误，而不是误报成已登录。

停止条件：页面白屏、登录成功后反复返回登录页、旧账号恢复、出现未知的 Cookie/Token
泄露迹象。遇到停止条件先关闭验证包，不继续开播。

## 第 2 轮：房间、推流地址和开播

人工操作：

1. 使用第 1 轮确认过的账号重新登录。
2. 确认房间标题、直播状态和分区列表已经读取。
3. 在 OBS 中准备一个最小场景，例如静态图片源；先确认预览可用。
4. 点击开始直播，观察 LiveHime 是否显示“正在申请推流地址”和 OBS 配置状态。
5. 在 Bilibili 客户端或网页确认房间已经进入直播状态。

通过条件：推流地址只在内存中传给 OBS；OBS 能连接并开始输出；服务器确认房间处于直播中；
界面显示与服务器状态一致。

如果 OBS 日志显示已经完成 RTMP 连接，但在首个视频或音频包写入后立即断开并进入重连，
先检查到 Bilibili 的实际网络出口和代理规则。部分推流 CDN 会按出口地域拒绝连接；代理
经过海外出口时可能出现“控制面开播成功、OBS 无限重连”的假象。切换到符合平台要求的
出口后再复测，不要在没有新推流配置的情况下反复点击开始直播。

若网络出口已确认可用但仍被首包断开，再把 OBS 的视频基准/输出分辨率和帧率降到直播姬
兼容基线 1280×720、30 fps 后复测；这是旧版 biliobs 的默认值，属于编码兼容排查项，
不要在尚未确认前覆盖用户现有 OBS 配置。

停止条件：推流密钥出现在诊断导出或普通界面日志、OBS 使用了旧地址、开播失败但房间状态
已经变成直播中、收到人脸验证或资格错误但没有对应提示。此时先点结束直播或关闭验证包，
不要重复点击开始直播。

## 第 3 轮：停止、自动关播和恢复

人工操作：

1. 点击“结束直播（关闭直播间）”。
2. 等待 OBS 确认停止，并等待 Bilibili 房间状态回读为非直播。
3. 再次登录后点击“退出登录（自动关播）”，确认已经离线时能正常退出。
4. 如果 OBS 停止卡住，只使用 LiveHime 的强制退出内置 OBS按钮；不要结束其他 OBS 进程。
5. 重新启动验证包，确认旧账号不会自动恢复，且不会把已经关闭的房间显示成直播中。

通过条件：OBS 和 Bilibili 都得到独立确认；任何一侧未确认时不会清除会话；强制退出失败时
不会被误报为已停止；Cookie 删除完成后才加载登录页。

## 记录格式

只记录以下信息即可：轮次、操作结果、界面状态、是否需要重试、脱敏后的 HTTP 状态/API code、
是否出现白屏或卡死。不要记录账号名、房间号、Cookie、Token、验证码、人脸凭证、推流地址或
推流密钥。

三轮通过后，才进入正式候选包评审。任何一轮失败都只新增一轮针对性回归，不重新无限重复
完整流程。
